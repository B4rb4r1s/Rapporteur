# Репортёр

Локальное приложение, которое по материалам научной конференции (презентации, записи выступлений, заметки слушателей) готовит справку: краткое описание каждого доклада, выводы и параметры конференции. Работает без внешних API.

- [Спецификация](docs/spec.md)
- [Бэклог Ф0–Ф1](docs/backlog.md)
- [Архитектурные решения](docs/adr/README.md)

## Что нужно

Docker с плагином compose и make. Python, Node и библиотеки на машину ставить не нужно: все проверки и сборки идут в контейнерах.

## Запуск dev без GPU

Из корня репозитория:

```bash
cp .env.example .env
make up
```

После успешного завершения `make up` интерфейс доступен на http://127.0.0.1:8000,
проверка backend — http://127.0.0.1:8000/health. Команда сначала поднимает БД и выполняет
`make migrate`, затем ждёт готовности `web`, `db`, `worker-cpu` и `worker-gpu`;
при ошибке сборки или healthcheck возвращает ненулевой код. Первая сборка требует
интернета для образов и зависимостей. БД и воркеры работают во внутренней сети `app`;
`web` дополнительно подключён к сети `edge` без NAT, только через неё публикуется порт.

`web` отдаёт собранный React и API одним процессом; Node во время работы не нужен.
PostgreSQL и артефакты хранятся в отдельных томах, порт базы на хост не публикуется.
В dev оба воркера работают без физических GPU. Заглушки `slides`, `notes`, `asr`
и `inventory` для демонстрационного снимка помечают результат `meta.stub=true`.
Для загруженных материалов `inventory` публикует реальные метаданные в обоих профилях.
Проверка цепочки «очередь → оба воркера → артефакты»:

```bash
make smoke
```

Планировщик `Scheduler.advance(conference_id)` учитывает граф, привязки файлов к докладам
и подтверждения человека. Команды `plan` и `advance` работают со снимком конференции;
[пример и инструкция](workers/README.md#планирование-графа) доступны без предметной БД.
CRUD конференций, секций, персон, докладов и справок, а также управление задачами доступны
через [API](docs/api.md). Из интерфейса можно загрузить материалы, подтвердить привязки и
запустить обработку. Сервис `scheduler` продвигает граф после завершения задач и
подтверждения привязок. Отдельные задания можно поставить через CLI.

## Запуск с GPU

В `.env` задайте `OLLAMA_MODELS_DIR` — внешний каталог с заранее подготовленными весами,
в котором лежат `blobs/` и `manifests/`. Ollama читает его без записи. На машине должен
быть NVIDIA Container Toolkit. Затем:

```bash
make up PROFILE=gpu
```

Подключается `deploy/compose.gpu.yaml`: Ollama и GPU-воркер получают доступ к GPU,
только GPU-воркер видит сеть Ollama. В этом режиме доступны настоящие обработчики
`slides` и `notes`; ASR пока не реализован. Шаги LLM доступны в CLI конвейера.
Для запуска этих шагов через воркеры предстоит подключить подготовку пакетов фрагментов.
`make smoke` работает только в dev. Образ Ollama и настройки — по
[ADR-010](docs/adr/ADR-010-inference-server.md).

`make ps` показывает состояние, `make logs` — логи, `make down` останавливает сервисы
и сохраняет данные PostgreSQL и артефакты. Для GPU используйте тот же `PROFILE=gpu`
в командах `down`, `ps`, `logs`, `config` и `migrate`.
`make config` проверяет конфигурацию без запуска
и без вывода пароля. `POSTGRES_PASSWORD` обязателен, образец в `.env.example` содержит
пароль только для локальной разработки. Смена пароля в `.env` при уже созданном томе
не меняет пароль базы. Адрес и порт интерфейса задаются `WEB_BIND_ADDRESS` и `WEB_PORT`;
по умолчанию интерфейс доступен только с локальной машины.

Миграции очереди можно выполнить отдельно командой `make migrate`. При обычном старте
приложения они не запускаются автоматически в каждом процессе. Сначала применяется
Alembic-миграция backend с пользователем `local`, затем миграция очереди. `/ready`
проверяет предметную схему БД; `/health` остаётся проверкой жизни процесса.

## Команды

| Команда | Что делает |
| --- | --- |
| `make up` | dev: web на http://127.0.0.1:8000, PostgreSQL и два воркера; без GPU |
| `make up PROFILE=gpu` | тот же запуск с настоящими обработчиками и Ollama |
| `make migrate` | отдельный шаг миграций backend и очереди перед запуском процессов |
| `make smoke` | сквозная проверка обоих dev-воркеров через очередь |
| `make down` | остановить dev, сохранив тома PostgreSQL и артефактов |
| `make config` | проверить конфигурацию dev без вывода подставленных переменных |
| `make check` | все проверки всех каталогов: линтеры, типы, тесты, актуальность сгенерированных контрактов, сборка фронтенда |
| `make lint` | только линтеры и проверка типов |
| `make test` | только тесты |
| `make -C backend run` | backend на http://127.0.0.1:8000, проверка — `/health` |
| `make -C pipeline graph` | проверка графа этапов `pipeline/graph.yaml` и порядок исполнения |
| `make -C pipeline run STAGE=slides INPUT=$PWD/data` | этап конвейера на папке с материалами; результаты в `pipeline/.rapporteur-data/`, вне git. `STAGE` — `slides` или `notes` |
| `make -C pipeline report INPUT=$PWD/data PROFILE=local-fast` | справка по папке через локальную модель: разбор, факты, сверка цитат, сводки, DOCX, Markdown и PDF в `pipeline/.rapporteur-data/exports/`. Нужен запущенный сервис `deploy/ollama`; `ARGS=--stub` — без модели |

У каждого каталога с кодом свой `Makefile` с теми же целями и `make lock` для обновления lock-файла.

## Перед слиянием в main

CI нет (ADR-011). Перед слиянием в `main` автор запускает `make check` на актуальной ветке и пишет результат в описании PR. Если меняются контракты или ADR, а другая команда PR не одобрила, изменение записывается в раздел «Взаимный просмотр» в [backlog.md](docs/backlog.md#взаимный-просмотр), в таблицу команды, которой предстоит просмотр.

## Каталоги

| Каталог | Что внутри |
| --- | --- |
| `contracts/` | контракты данных: Pydantic-модели, JSON Schema, TS-типы, примеры |
| `pipeline/` | этапы конвейера без веба и БД, CLI `rapporteur run` и `rapporteur report`: разбор презентаций и заметок, факты и сводки через Ollama, сверка цитат, сборка справки по бланку |
| `prompts/` | промпты шагов сводки с версиями ([README](prompts/README.md)) |
| `templates/` | бланки справки: DOCX и `variables.yaml`, правила в [templates/README.md](templates/README.md) |
| `backend/` | FastAPI, предметная БД, Alembic и HTTP API; схема в openapi.json |
| `workers/` | очередь PostgreSQL, CLI постановки заданий и CPU/GPU-исполнители |
| `frontend/` | React + Vite + TypeScript |
| `deploy/` | общий Compose, GPU-дополнение с Ollama, образ web со статикой |
| `docs/` | спецификация, бэклог, ADR, замеры |

Каталоги из spec §8.4 появляются по мере появления кода. `data/` и `docs/SoW/` в git не входят.
