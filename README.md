# Репортёр

Локальное приложение, которое по материалам научной конференции (презентации, записи выступлений, заметки слушателей) готовит справку: краткое описание каждого доклада, выводы и параметры конференции. Работает без внешних API.

- [Спецификация](docs/spec.md)
- [Бэклог Ф0–Ф1](docs/backlog.md)
- [Архитектурные решения](docs/adr/README.md), устройство приложения — [ADR-014](docs/adr/ADR-014-simplification.md)
- [API](docs/api.md)

## Что нужно

Docker с плагином compose, make и NVIDIA Container Toolkit. Python, Node и библиотеки на машину ставить не нужно: сборка и проверки идут в контейнерах.

## Запуск

```bash
cp .env.example .env
```

В `.env` укажите `OLLAMA_MODELS_DIR` — каталог с весами Ollama (`blobs/` и `manifests/`). Ollama читает его без записи. На машине с интернетом модель можно скачать командой `make pull MODEL=qwen3.5:9b`.

```bash
make up
```

Интерфейс откроется на http://127.0.0.1:8000. Адрес и порт задаются `WEB_BIND_ADDRESS` и `WEB_PORT`, по умолчанию интерфейс доступен только с локальной машины.

В интерфейсе:

- «Конференции» — список, создание и удаление.
- В конференции:
  - «Материалы» — загрузка папки и подтверждение привязок;
  - «Обработка» — ход по докладам, повтор при ошибке, проверка и правка сводок;
  - «Справка» — даты, сборка, версии DOCX, Markdown и PDF.
- «Управление» — тема, доступность Ollama, профили моделей, бланки.

В папке конференции у каждого доклада своя подпапка: `Иванов/` или `Секция/01_Иванов/`.

## Как устроено

Два сервиса в одном [compose.yaml](compose.yaml):

- `app` — FastAPI, собранный React и фоновая обработка в одном процессе. База SQLite, оригиналы, кэш шагов и справки лежат в томе `data`.
- `ollama` — модель. Работает во внутренней сети без выхода наружу.

После подтверждения привязок и запуска обработки каждый доклад проходит цепочку: разбор презентаций и заметок → пакет фрагментов → факты и цитаты (LLM) → сверка цитат кодом → текст сводки (LLM). Результаты шагов кэшируются: повтор не обращается к модели, если входы не изменились. Профиль модели по умолчанию задан в [profiles.yaml](profiles.yaml), промпты лежат в [prompts/](prompts/README.md), бланк справки — в [templates/](templates/README.md).

| Каталог | Что внутри |
| --- | --- |
| `src/rapporteur/contracts/` | Pydantic-модели: сущности, фрагменты, утверждения, сводки, справка |
| `src/rapporteur/ingest/` | приём файлов, разбор pptx, pdf и заметок, рендер слайдов |
| `src/rapporteur/summarize/`, `llm/` | пакет фрагментов, факты, сверка цитат, сводка, клиент Ollama |
| `src/rapporteur/report/` | переменные, склонения, бланк DOCX, Markdown и PDF |
| `src/rapporteur/*.py` | приложение: API (`app.py`), база (`db.py`), материалы, обработка, сводки, справки |
| `tests/` | тесты; модель в них заменяет `ScriptedClient` |
| `frontend/` | React + Vite + TypeScript |
| `docs/` | спецификация, бэклог, ADR, замеры |

`data/` и `docs/SoW/` в git не входят.

## Команды

| Команда | Что делает |
| --- | --- |
| `make up` | собрать и запустить приложение и Ollama, дождаться готовности |
| `make down` | остановить; база, материалы и справки остаются в томе `data` |
| `make ps`, `make logs` | состояние и журнал сервисов |
| `make config` | проверить `compose.yaml` и `.env` без запуска |
| `make check` | ruff, mypy, pytest, eslint, tsc, vitest и сборка фронтенда в контейнерах |
| `make format` | поправить стиль Python |
| `make pull MODEL=…` | скачать модель в `OLLAMA_MODELS_DIR` (нужен интернет) |
| `make lock` | обновить `uv.lock` и `frontend/package-lock.json` после правки зависимостей |

## Перед слиянием в main

CI нет (ADR-011). Перед слиянием в `main` автор запускает `make check` на актуальной ветке и пишет результат в описании PR. Если меняются контракты или ADR, а другая команда PR не одобрила, изменение записывается в раздел «Взаимный просмотр» в [backlog.md](docs/backlog.md#взаимный-просмотр), в таблицу команды, которой предстоит просмотр.

Ветки, коммиты и уборка после слияния — в [docs/git.md](docs/git.md).
