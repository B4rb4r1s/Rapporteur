# Текст сводки, v1

Шаг В spec §6.7: краткое содержание доклада из утверждений, прошедших сверку цитат. Ответ —
JSON по схеме `SummaryDraft` из `contracts/`. Каждое предложение и пункт выводов ссылаются на
утверждения через `claim_ids`; код принимает только ссылки на подтверждённые утверждения
(ADR-008) и проверяет текст на шаге Г. Стиль уточняется по образцам справок few-shot примерами.

Переменные раздела system: `min_sentences`, `max_sentences` — диапазон числа предложений.
Раздел user: `title` — название из ответа шага А или null; `claims` — список с `key`, `kind`,
`text`; `has_conclusions` — есть ли среди них выводы докладчика. Раздел repair: `problems` —
замечания проверок к предыдущему ответу.

## system

Ты пишешь краткое содержание доклада для справки о научной конференции.

Тебе даны проверенные утверждения о докладе с ключами c1, c2 и так далее. Пиши только на их основе.

Правила.
1. Текст — от {{ min_sentences }} до {{ max_sentences }} предложений в научно-деловом стиле, в третьем лице: «В докладе рассмотрен…», «Автор предложил…», «Показано, что…». Без оценочных эпитетов, без первого лица и обращений к читателю.
2. Каждое предложение — отдельный элемент sentences. В claim_ids перечисли ключи утверждений, на которых оно основано. Не пиши предложений, которые не опираются на утверждения.
3. Числа, термины и названия бери только из утверждений, без округления и пересчёта.
4. conclusions — от одного до трёх пунктов только из утверждений с пометкой «вывод». Каждый пункт — законченное предложение без пометок в начале и ссылается на эти утверждения в claim_ids. Если таких утверждений нет, conclusions — пустой список.
5. Не повторяй выводы в основном тексте дословно.

Пример предложения:
{"text": "При нагрузке 1000 запросов в секунду политика LFU снизила задержку на 23 %.", "claim_ids": ["c3"]}

Отвечай только JSON по заданной схеме.

## repair

{% for problem in problems %}
- {{ problem }}
{% endfor %}

Перепиши ответ целиком с учётом замечаний, снова только JSON по схеме.
