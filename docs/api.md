# API

Базовый префикс — `/api/v1`. Схема в работающем приложении — `GET /openapi.json`;
Swagger с CDN отключён. Одна общая рабочая область, без входа и ролей (ADR-011).
Устройство приложения описано в ADR-014.

`GET /health` — проверка жизни процесса: `{"status": "ok", "version": ...}`.

Ошибка — `{"message": "текст для пользователя"}` с кодом:

| Код | Когда |
| --- | --- |
| 404 | конференции, доклада, сводки, файла или версии справки нет |
| 409 | сводку уже изменили; по пути уже загружен другой файл; доклад уже в обработке |
| 413 | файл больше лимита (spec §5.4) |
| 415 | загрузка не как `application/octet-stream` |
| 422 | неверные входные данные, формат файла не поддерживается, справку нельзя собрать |

## Конференции

| Запрос | Что делает |
| --- | --- |
| `GET /conferences` | список с числом докладов, сводок и проверенных докладов, новые сверху |
| `POST /conferences` | создать: `title`, `start_date`, `end_date`, `place`, `organizer` (всё необязательно); 201 |
| `GET /conferences/{id}` | конференция со счётчиками |
| `PUT /conferences/{id}` | заменить метаданные целиком; конец раньше начала — 422 |
| `DELETE /conferences/{id}` | удалить вместе с секциями, докладами, файлами, сводками и версиями справки; 204 |

## Материалы и реестр

`POST /conferences/{id}/materials?path=Секция/01_Иванов/доклад.pptx[&program=true]`
принимает тело файла как `application/octet-stream` потоком. Тип файла определяется
по содержимому. Ответ — `SourceFile`: 201 для нового файла, 200 для повтора того же
содержимого. Папка доклада (`Иванов/` или `Секция/01_Иванов/`) создаёт секцию и доклад
реестра. Название доклада берётся с титульного слайда, иначе из имени папки. Файлы
из `_общее/` и программа к докладу не привязываются.

`GET /conferences/{id}/materials` — снимок для проверки привязок:
`processing_started`, `files[]`, `sections[]`, `talks[]`. Для каждого файла: `binding`
(текущая привязка и подтверждена ли она), `suggested_talk_id` и `confidence` (подсказка),
`alternate_of` (PDF-копия презентации).

`PUT /conferences/{id}/materials/bindings` с `{"bindings": [{"source_file_id", "talk_id"}]}`
подтверждает решение по каждому файлу конференции. Статусы докладов пересчитываются:
с презентацией или записью доклад переходит в `matched`, без них — в `insufficient_data`.
У обработанного доклада смена материалов даёт `stale`. Если обработка уже запущена, готовые
доклады сразу встают в очередь.

`POST /conferences/{id}/talks` с `{"title", "section_id"?}` добавляет доклад вручную
и возвращает снимок материалов. `PUT /talks/{id}` с `{"title", "speakers": [{"name",
"affiliation", "role"}]}` меняет название и докладчиков реестра: они идут в справку.

`GET /conferences/{id}/conference.yaml` — реестр в формате spec §7.4.

## Обработка

`POST /conferences/{id}/processing` запускает обработку конференции: доклады
в `matched` и `stale` встают в очередь. Ответ 202 — ход обработки.

`GET /conferences/{id}/progress` — `processing_started`, `files` (число файлов) и по каждому
докладу: `status`, `job` (`queued`, `running`, `done`, `failed`), `step` (`parse`, `facts`,
`verify`, `summary`), `error` (`код: сообщение`), `summary_number`, `summary_status`.

`POST /talks/{id}/retry` ставит доклад в очередь заново (202). Результаты шагов с теми же
входами берутся из кэша, модель повторно не вызывается.

## Сводки

`GET /talks/{id}/summary` — текущая версия: `summary` (контракт `Summary`), `pack`
(пакет фрагментов, по которому она собрана), `talk_title`, `talk_status`.

`PUT /talks/{id}/summary` с `{"version", "sentences", "conclusions", "claims": [{"key",
"text"}]}` создаёт новую версию с правкой человека. `version` — номер версии, которую видел
человек; если сводку уже изменили, ответ 409. Ссылки на неизвестные или отклонённые
утверждения — 422. Правка проверенной сводки возвращает доклад в `processed`.

`POST /talks/{id}/summary/review` с `{"version"}` подтверждает проверку: утверждения
из текста получают `confirmed`, доклад — `reviewed`.

`GET /files/{id}/slides/{n}` — PNG слайда из разбора презентации.

## Справка

`POST /conferences/{id}/reports` с `{"unreviewed_confirmed": false, "talk_ids": null}`
собирает справку по бланку прямо в запросе. Без `talk_ids` берутся все доклады
конференции. Ответ 201 — версия: `number`, снимок входа `input`, переменные `variables`,
файлы DOCX, Markdown и PDF, `warnings`. Нет готовых сводок, есть непроверенные доклады
без подтверждения или нет дат конференции — 422 с объяснением.

`GET /conferences/{id}/reports` — версии справки, новые сверху.
`GET /report-versions/{id}/files/{docx|md|pdf}` — файл версии.

## Модель для сводок

`GET /model` — `current` (модель, режим рассуждения, профиль и `chosen` — выбрана ли она
на странице «Управление»), `default` (профиль по умолчанию из `profiles.yaml`),
`ollama_available` и `models` — модели Ollama с размером, квантованием и признаком
`thinking` (есть режим рассуждения).

`PUT /model` с `{"model": "qwen3.5:9b", "reasoning": true}` выбирает модель: она заменяет
в профиле по умолчанию модель, ревизию весов и режим рассуждения. `{"model": null}`
возвращает профиль из `profiles.yaml`. Модели нет в Ollama или рассуждение у модели
без режима рассуждения — 422; Ollama недоступна — 503. Выбор действует на доклады,
которые обрабатываются после сохранения.

## Состояние

`GET /system` — версия приложения, адрес и доступность Ollama, загруженные модели,
профили из `profiles.yaml`, бланки из `templates/`, число докладов в очереди, в работе
и с ошибкой.
