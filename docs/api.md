# API MVP

Базовый префикс — `/api/v1`. Машиночитаемая спецификация: `backend/openapi.json`,
в работающем сервисе — `GET /openapi.json`. Интерфейс Swagger с CDN отключён.
В MVP одна общая рабочая область, без входа и ролей (ADR-011).

## Запуск

Общий Compose: скопировать `.env.example` в `.env`, выполнить `make up`.
Он отдельно применяет миграции backend и очереди перед запуском процессов.
Только backend: `make -C backend run`; миграция запускается через отдельную цель migrate.
По умолчанию HTTP слушает `127.0.0.1:8000`. Адрес и порт задаются WEB_BIND_ADDRESS и WEB_PORT.

Для прямого запуска без Compose задайте DATABASE_URL с драйвером postgresql+psycopg
либо PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD, затем `rapporteur-backend migrate`.
`/health` проверяет жизнь процесса, `/ready` — БД и совместимость миграции.

## CRUD

| Ресурс | Создать / список | Прочитать / заменить / удалить |
| --- | --- | --- |
| Конференции | POST /conferences, GET /conferences | GET, PUT, DELETE /conferences/{id} |
| Секции | POST, GET /conferences/{id}/sections | GET, PUT, DELETE /sections/{id} |
| Персоны | POST /people, GET /people | GET, PUT, DELETE /people/{id} |
| Доклады | POST, GET /sections/{id}/talks | GET, PUT, DELETE /talks/{id} |
| Справки | POST, GET /conferences/{id}/reports | GET, PUT, DELETE /reports/{id} |
| Версии справки | GET /reports/{id}/versions | Версии неизменяемы, запись из обработчика сборки |

Все пути таблицы относительно /api/v1. POST возвращает 201 и ресурс по контракту,
PUT — 200, DELETE — 204. Поля тела POST/PUT описаны в OpenAPI: служебные id, version,
owner_id, author_id и edited_by в запросах запрещены. PUT заменяет редактируемые поля
целиком; отсутствующие необязательные поля получают значения по умолчанию.

Создание конференции допускает пустые метаданные. Новый доклад получает draft; можно
явно создать insufficient_data с названием. Дальнейшие переходы соответствуют таблице
can_transition из contracts. Участники ссылаются на существующих персон, роль speaker
или coauthor; участники и позиции внутри роли уникальны. В конференции не больше пяти секций.

Report хранит выборку и версию бланка. Все выбранные доклады и секции должны принадлежать
конференции; если days/section_ids непустые, доклады должны соответствовать фильтрам.
Дата доклада по умолчанию — дата секции. Краткие тексты и файлы создаёт конвейер;
ручной ввод произвольной справки через CRUD не поддерживается.

У всех списков параметры `limit=50` (1…100), `offset=0` (неотрицательный).
Ответ: `{items: [...], page: {total, limit, offset}}`. Порядок стабилен:
секции/доклады — order и UUID, остальные предметные объекты — UUID,
версии справки — номер по убыванию.

## Версии и конфликты

POST, GET одного объекта и PUT возвращают ETag, например `"1"`. Каждый PUT и DELETE
требует `If-Match: "1"`; слабый ETag и неполный/отсутствующий заголовок отклоняются с 422.
После PUT версия увеличивается. Устаревший If-Match даёт 409 version_conflict,
данные не перезаписываются. Section и Person сохраняют прежний публичный контракт:
их версия передаётся только в ETag. Родительский UUID при PUT не меняется.

Пример:

```http
POST /api/v1/conferences
Content-Type: application/json

{"title":"Конференция","start_date":"2026-11-04","end_date":"2026-11-05"}
```

Из ответа возьмите id и ETag. Для замены:

```http
PUT /api/v1/conferences/{id}
Content-Type: application/json
If-Match: "1"

{"title":"Уточнённое название","start_date":"2026-11-04","end_date":"2026-11-05"}
```

Удаление конференции каскадно удаляет секции, доклады, справки и их версии. Персону,
используемую докладом, или доклад/секцию из выборки справки отдельно удалить нельзя:
422 validation_error. Сначала измените ссылки. Оригинальные файлы на томе не удаляются.

## Задачи

| Метод и путь | Действие |
| --- | --- |
| GET /jobs | Список; фильтры conference_id, status, resource; пагинация |
| GET /jobs/{id} | Job по контракту |
| POST /jobs/{id}/cancel | 202 JobAccepted; queued/retry_wait отменяются сразу, running → cancel_requested |
| POST /jobs/{id}/retry | 202 JobAccepted; failed/cancelled → queued, lease и ошибки сброшены |
| PUT /jobs/{id}/priority | Тело `{priority: 100}`; 200 Job, только queued/retry_wait |

Статусы проверяются атомарно под блокировкой строки. Команда для неподходящего состояния
даёт 409. Повтор cancel уже отменённой задачи возвращает тот же JobAccepted. Повтор retry
не создаёт второе задание: после первого перехода в queued следующий запрос получит 409.
Управление lease остаётся у воркеров; наружу не выдаётся lease_token.
Если миграция очереди не выполнена, маршруты задач возвращают ошибку настройки, без заглушки.

## Ошибки

Форма: `{code, message, details, request_id}`. Заголовок X-Request-ID совпадает с request_id
и доступен также при успешном ответе. В details ошибок 422 указаны путь поля и тип ошибки;
исходные значения, SQL и реквизиты подключения в ответ не входят.

| HTTP | code | Когда |
| --- | --- | --- |
| 404 | not_found | Объекта или маршрута нет |
| 409 | version_conflict | Устаревшая версия или недопустимый переход состояния |
| 422 | validation_error | Поля, ссылки, выборка, ограничения БД |
| 405 | validation_error | Метод для маршрута не поддерживается; Allow сохраняется |
| 500 | internal_error | БД/миграции/настройка или внутренняя ошибка, без текста драйвера |

Загрузка и привязка файлов, фрагменты, сводки и их редактор, сборка и скачивание файлов,
подтверждения человека и состояние GPU подключаются следующими задачами плана.

## Проверки

`make -C backend check` — Ruff, mypy, тесты с отдельным PostgreSQL.
`make -C backend openapi` — обновить сохранённую схему. Тест проверяет её актуальность.
Тестовая цель использует отдельный Compose-проект rapporteur-backend-check и после
проверок удаляет только его контейнеры и том. Контейнерный make check требует машины с Docker.
