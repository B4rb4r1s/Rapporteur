# Ollama: своя или другого проекта

## Своя Ollama (по умолчанию)

`make up` запускает приложение и свою Ollama (ADR-010). Модели лежат в каталоге
`OLLAMA_MODELS_DIR` на хосте, Ollama читает его без записи. Новая модель скачивается
командой `make pull MODEL=…` в этот же каталог на хосте; для этого каталог должен быть
доступен на запись пользователю `HOST_UID`.

Ollama работает во внутренней сети Docker и доступна приложению по адресу `ollama:11434`.
Порт на хосте она не публикует, поэтому другая Ollama на порту 11434 ей не мешает.
Менять порт не нужно.

## Ollama другого проекта

Если на машине уже работает Ollama другого проекта в Docker, приложение может пользоваться
ей вместо своей. Тогда своя Ollama не запускается, и две Ollama не делят память GPU.

1. Узнайте сеть Docker и имя сервиса чужой Ollama:

   ```bash
   docker ps --format '{{.Names}}\t{{.Networks}}'
   ```

2. Задайте в `.env`:

   ```bash
   OLLAMA_NETWORK=kgs_default
   OLLAMA_URL=http://ollama:11434
   ```

   `OLLAMA_URL` — имя контейнера или сервиса чужой Ollama в этой сети и её порт внутри
   контейнера, обычно 11434. `OLLAMA_MODELS_DIR` в этом режиме не нужен.

3. Перезапустите:

   ```bash
   make down
   make up
   ```

   Make запустит сервис `app-shared`: то же приложение с тем же хранилищем `storage/`, подключённое
   к сети чужой Ollama. `make ps`, `make logs` и `make down` работают как обычно, `make start`
   на машине без интернета — тоже.

Чтобы вернуть свою Ollama, удалите `OLLAMA_NETWORK` из `.env` и снова выполните
`make down` и `make up`.

### Что учесть

- **Модели.** Нужны модели чужой Ollama. Если модели из `profiles.yaml` там нет, выберите
  другую на странице «Управление»: там же видно, доступна ли Ollama и что в ней есть.
- **Настройки.** `OLLAMA_NUM_PARALLEL`, `OLLAMA_KEEP_ALIVE` и контекст по умолчанию задаёт
  тот проект. Длину контекста приложение передаёт в каждом запросе само.
- **Сеть.** Чужая сеть может иметь выход в интернет, и тогда он появится у приложения.
  Для изолированной установки (spec §2) сеть другого проекта должна быть внутренней.
- **Совместная работа.** Запросы двух проектов идут в одну очередь Ollama: пока другой
  проект занимает модель, обработка докладов ждёт.
