# ADR-003. Контракт фрагментов и ссылок на источник

- Статус: Принято
- Дата: 2026-10-27
- Ведёт: К1 · лид
- Связано: spec §3 (п. 4), §6.7, §7.3, ADR-007

## Контекст

Каждое утверждение справки должно опираться на конкретное место в источнике. Исходные ТЗ предлагали разное:

- ТЗ команды 1: модель возвращает метку и цитату, код ищет цитату нечётким сравнением.
- ТЗ команды 2: ссылка — диапазон символов в неизменяемой ревизии фрагмента.

Модели плохо считают смещения символов, но хорошо копируют короткие цитаты. Правка стенограммы человеком не должна ломать проверяемость старых сводок.

## Варианты

1. Только метка и цитата: просто, но ссылка не привязана к версии текста.
2. Только диапазон символов от модели: точная привязка, но модель ошибается в смещениях.
3. Гибрид: модель даёт метку и цитату, код находит диапазон в конкретной ревизии.

## Решение

Гибрид (вариант 3).

**Фрагмент** — единица источника:

| Поле | Значение |
| --- | --- |
| `id` | UUID |
| `kind` | `slide`, `transcript`, `note`, `program` |
| `label` | метка для модели: `S12` (слайд 12), `S2.12` (слайд 12 второй презентации доклада), `T00:12:34` (начало отрезка стенограммы около 30–60 с), `N3` (заметка 3) |
| `source_file_id` | исходный файл |
| `locator` | слайд или страница; начало и конец в мс; строки заметки |

**Ревизия фрагмента** неизменяема: номер, сырой текст, нормализованный текст, автор правки, время. Правка создаёт новую ревизию.

**Ссылка на источник:**

| Поле | Кто заполняет |
| --- | --- |
| `label`, `quote` | модель |
| `fragment_revision_id` | код: ревизия, по которой собиралась сводка |
| `span` | код: `[start, end)` в кодовых точках Unicode нормализованного текста |
| `match_score` | код: оценка rapidfuzz |

Правила:

- Нормализация перед поиском: нижний регистр, ё → е, пунктуация убрана, пробелы схлопнуты, кавычки и тире унифицированы; цифры сохраняются.
- Цитата ищется только во фрагментах этого доклада и только по указанной метке; порог совпадения настраивается.
- Ниже порога утверждение отклоняется или уходит на перегенерацию.
- Номер слайда, таймкод и путь к файлу сервер берёт из локатора. Модель не формирует URL, имена файлов и номера страниц.
- Правка текста утверждения снимает его подтверждение.
- Новая ревизия источника не меняет старую сводку: сводка получает статус «устарел».
- Фронтенд переводит `span` из кодовых точек в смещения UTF-16 при подсветке.

## Последствия

- Контракт входит в `contracts/` и меняется только с одобрения обеих команд.
- Нужны тесты: точная цитата, слегка искажённая цитата, выдуманная цитата, цитата из другого доклада, цитата с ё и е, суррогатные пары при подсветке.

## Когда пересмотреть

Если доля ложных отклонений на эталоне высока и порог не помогает, рассмотреть поиск по токенам или выравнивание последовательностей вместо rapidfuzz.
