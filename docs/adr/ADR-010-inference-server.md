# ADR-010. Сервер инференса: Ollama вместо vLLM

- Статус: Предложено; решение команды 1 принято, ждёт одобрения команды 2
- Дата: 2026-11-01
- Ведёт: К1 · лид, замеры К2 · A
- Связано: spec §2, §6.7, §8, §9, ADR-001, ADR-002, [локальная проверка](../benchmarks/ollama-facts-schema-local.md)

## Контекст

ADR-001 закрепил vLLM, ADR-002 построил на нём режимы работы двух A100. Команда 1 решила запускать модели через Ollama в контейнере с внешней папкой весов: так проще управлять моделями.

| Требование | Ollama |
| --- | --- |
| BF16 без квантизации (§9) | в библиотеке есть `qwen3.6:27b-bf16` (56 ГБ) и `qwen3.6:35b-a3b-bf16` (72 ГБ) |
| Две карты | модель, не влезшая на одну карту, распределяется по всем; `OLLAMA_SCHED_SPREAD` включает это принудительно; tensor parallel в документации не описан |
| Параллельные запросы | `OLLAMA_NUM_PARALLEL`, по умолчанию 1; память растёт как параллельность × контекст |
| JSON Schema | `format` в `/api/chat`, проверено локально на `FactsDraft` |
| Рассуждение вместе со схемой | работает на 0.40.13, на 0.30.11 схема без рассуждения не применялась |
| Смена модели | имя в запросе, простаивающая модель выгружается сама; загрузка заново с диска |
| Управление весами | внешний каталог через `volumes`, хранилище с адресацией по SHA-256 |
| Офлайн (§2) | внутренняя сеть контейнера, `OLLAMA_NO_CLOUD=1`, готовый каталог моделей |

## Варианты

1. Оставить vLLM (ADR-001).
2. Заменить vLLM на Ollama.
3. Держать оба движка за одним клиентом и выбрать для сервера по замеру. Это откладывает решение ценой двух движков в настройке и офлайн-поставке.

## Решение

Вариант 2. Решение принято командой 1 до замера на сервере, поэтому замер P0-03 проверяет его, а не выбирает движок.

1. Сервис `ollama` заменяет `vllm`. Описание сервиса — [deploy/ollama/compose.yaml](../../deploy/ollama/compose.yaml), P1-01 включает его в общий compose.
2. Модели лежат во внешнем каталоге, подключённом через `volumes` (`OLLAMA_MODELS_DIR`). Рабочая сеть внутренняя, порт наружу не публикуется, сервис `pull` работает только на машине с интернетом.
3. Клиент-абстракция работает с `/api/chat`: там доступны `think`, `format`, `keep_alive` и `num_ctx`. Движок остаётся полем профиля модели, поэтому конвейер и контракты от него не зависят.
4. Образ закреплён по digest на версии 0.40.13. Версия 0.30.11 не подходит: при `think=false` она не применяла `format`.
5. worker-gpu управляет загрузкой через `keep_alive` и `/api/ps`. Управляющий процесс из ADR-002 не нужен.
6. Ответ, оборванный лимитом токенов (`done_reason=length`), считается ошибкой: на рассуждение может уйти весь лимит, и тогда ответ приходит пустым.

## Проверено локально

На RTX 3060 с `qwen3.5:9b` и Ollama 0.40.13 схема `FactsDraft` соблюдена в 12 ответах из 12, с рассуждением и без него. Сообщение о нестрогой схеме для Qwen 3.5 не подтвердилось. Подробности — в [отчёте](../benchmarks/ollama-facts-schema-local.md).

Это проверка механизма. Целевая модель, две карты и параллельная нагрузка не проверялись.

## Последствия

- Проще: смена моделей, поставка весов каталогом, нет управляющего процесса, один движок.
- Теряется tensor parallel и пакетная обработка vLLM. Насколько это скажется на A100, неизвестно: сторонние замеры показывают заметный отрыв vLLM под параллельной нагрузкой, но их цифры расходятся и не воспроизводились.
- Нет sleep mode: смена модели идёт через выгрузку и загрузку. Планировщик тем более должен группировать задачи по профилю (ADR-002).
- Меняются ADR-001, ADR-002, spec §2, §6.7, §8, §9, задачи P0-03, P0-05, P0-07, P1-01. Работа К2 · A по vLLM отпадает, по Ollama добавляется.
- Рассуждение на коротком докладе заняло около 5 тыс. токенов. Резерв 8K из §6.7 проверяется на реальных докладах.

## Когда пересмотреть

После P0-03 и P1-10, если выполняется хотя бы одно условие:

- на `qwen3.6:27b-bf16` меньше 100% ответов шага А проходят схему;
- контекст 32K не держится при нужной параллельности;
- прогноз обработки 100 докладов не укладывается в ночь.

Тогда вернуться к вариантам 1 или 3: код обращается к модели только через клиент, поэтому затронуты будут клиент, сервис и поставка весов.
