# ADR-005. Хранение файлов на томе и кэш этапов

- Статус: Принято; кэш шагов уточнён ADR-014
- Дата: 2026-10-27
- Ведёт: К2 · A
- Связано: spec §3 (п. 6), §6.1, §8.2, §13, ADR-006

## Контекст

- Один сервер, файлы большие: многочасовые записи и видео до 10 ГБ.
- Пользователей много, и несколько сотрудников могут загрузить одну и ту же запись одной конференции. Распознавать её дважды дорого.
- Этапы конвейера идемпотентны, перезапуск возможен с любого этапа.
- ТЗ команды 2 предлагало MinIO с карантином и presigned-загрузками; ТЗ команды 1 — том Docker.

## Варианты

1. MinIO с бакетами для оригиналов, производных файлов и выгрузок.
2. Том Docker с адресацией по хэшу и интерфейсом хранилища, за которым позже можно поставить MinIO.

## Решение

Том Docker (вариант 2).

```
/data/
  blobs/<sha256[:2]>/<sha256>          оригиналы, неизменяемые
  derived/<cache_key>/…                производные файлы: PNG слайдов, нормализованный звук
  artifacts/<stage>/<cache_key>.json   артефакты этапов
  exports/<report_version_id>/…        выдача справок
  tmp/                                 временные файлы, очистка через 24 ч
```

- Оригинал хранится один раз по SHA-256; конференции ссылаются на него через собственную запись `SourceFile` в БД.
- Артефакты кэша не содержат идентификаторов конференции: фрагменты в них лежат без UUID и меток, слой конференции создаёт воркер (ADR-008).
- Ключ кэша этапа — хэш от хэшей входов, имени и версии обработчика и хэша конфигурации. Совпал ключ — этап не выполняется повторно. У этапа доклада в ключ входит и id доклада: его выход зависит от доклада, а не только от входов (уточнение ADR-013).
- Кэш переиспользует вычисления, а не доступ: пользователь видит только свои конференции (ADR-006; в MVP рабочая область общая, ADR-011), а повторное использование распознавания возможно лишь для файла, который он сам загрузил.
- Весь доступ к файлам идёт через интерфейс `Storage` (put, get, exists, delete); прямых путей в бизнес-логике нет.
- Файл без ссылок удаляется плановой задачей; удаление материала помечает зависимые сводки и справки устаревшими.

## Последствия

- Дедупликация и кэш получаются бесплатно из адресации по хэшу.
- Бэкап: `pg_dump`, затем копия тома. Оригиналы и артефакты неизменяемы, поэтому порядок «сначала БД, потом файлы» даёт согласованную копию.
- Нет presigned-загрузок и отдельного карантинного бакета: файл принимает `web`, проверяет лимиты и тип по содержимому до записи в `blobs/`.

## Когда пересмотреть

- Файлы перестают помещаться на один сервер.
- Появляется второй сервер с воркерами, которому нужен общий доступ к файлам.
