# Бэклог Ф0–Ф1

Задачи первых двух фаз из [спецификации](spec.md), §15. Задачи следующих фаз расписываются к концу Ф1, когда появятся замеры.

**Роли.** К1 · лид и К1 · разработчик — команда 1; К2 · A (инфраструктура, GPU, приём файлов, речь) и К2 · B (backend и frontend) — команда 2. Распределение внутри команды 1 предварительное (spec §14).

**Пока команда 2 не подключилась** (ADR-011), все задачи ведёт команда 1, а поле «Ведёт» показывает постоянного владельца потока. Ревью команды 2 переносится на момент подключения; изменения контрактов и ADR, принятые без неё, записываются в раздел [«Ждёт просмотра командой 2»](#ждёт-просмотра-командой-2).

**Формат задачи.** Цель, ведущий и ревьюер, зависимости, вход и выход, позитивные и негативные проверки, критерий готовности. Задача берётся, когда выполнены её зависимости. Статус меняется в этом файле в том же PR, что и код. Перед слиянием в `main` автор запускает `make check` и пишет результат в описании PR.

**Статусы:** не начата · в работе · на ревью · готова.

### P1-02. Очередь на PostgreSQL

- **Ведёт:** К2 · A. **Ревью:** К1 · лид.
- **После:** P1-01, P0-08.
- **Цель:** надёжная очередь по ADR-004 и исполнение графа по ADR-009.
- **Выход:** `workers/src/rapporteur_workers/queue.py` — таблица задач, захват через `SKIP LOCKED`, lease и heartbeat, повторы с backoff, отмена, приоритеты; `advance(conference_id)` поверх графа этапов; выбор «своя реализация или procrastinate» записан в ADR-004.
- **Проверки:**
  - [x] повторный вызов `advance` не создаёт дублей задач, а этапы после проверки человека не запускаются до её прохождения;
  - [ ] убитый воркер — задача возвращается в очередь после истечения lease;
  - [ ] короткая интерактивная задача обгоняет длинную пакетную;
  - [ ] невалидный вход не повторяется;
  - [ ] старый воркер не перезаписывает результат новой попытки;
  - [ ] результат отменённой задачи не публикуется.
- **Готово, когда:** тесты на эти сценарии проходят в `make check`.
- **Промежуточный результат:** своя очередь на Psycopg 3, отдельная SQL-миграция схемы `rapporteur_queue`, `SKIP LOCKED`, lease и heartbeat, fencing по UUID попытки, backoff и jitter, отмена и приоритеты. Планировщик `Scheduler.advance(conference_id)` разворачивает граф по снимку конференции, учитывает области зависимостей, статусы, проверки человека и отсутствие входов; конкурентные вызовы не создают дубликатов. CLI поддерживает plan/advance, для dev есть заглушка inventory и пример снимка. Общий кэш публикуется под advisory-блокировкой без изменения SHA ранее сохранённых ссылок. Прошли 58 тестов workers на PostgreSQL 17.11, Ruff и mypy. Адаптер предметной БД, автоматические вызовы после завершения/подтверждения и группировка по профилю модели ещё не подключены; корневой `make check` требует Docker. P1-02 остаётся в работе.
