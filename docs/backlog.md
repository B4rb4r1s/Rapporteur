# Бэклог Ф0–Ф1

Задачи первых двух фаз из [спецификации](spec.md), §15. Задачи следующих фаз расписываются к концу Ф1, когда появятся замеры.

**Роли.** К1 · лид и К1 · разработчик — команда 1; К2 · A (инфраструктура, GPU, приём файлов, речь) и К2 · B (backend и frontend) — команда 2. Распределение внутри команды 1 предварительное (spec §14).

**Формат задачи.** Цель, ведущий и ревьюер, зависимости, вход и выход, позитивные и негативные проверки, критерий готовности. Задача берётся, когда выполнены её зависимости. Статус меняется в этом файле в том же PR, что и код.

**Статусы:** не начата · в работе · на ревью · готова.

## Ф0. Замеры и контракты (неделя 1)

### P0-01. Контракты v0

- **Ведёт:** К1 · лид. **Ревью:** К2 · A, К2 · B.
- **После:** —
- **Цель:** общий язык данных для обеих команд, чтобы дальше работать параллельно.
- **Вход:** spec §7, ADR-003, ADR-006, ADR-007.
- **Выход:** `contracts/` — Pydantic-модели Conference, Section, Talk, Person, SourceFile, Segment, SourceFragment, FragmentRevision, Claim, Evidence, Summary, Report, Job и входов-выходов этапов; JSON Schema; TS-типы; примеры в `contracts/examples/`; формат ошибок API; `contracts/VERSION` = 0.1.0.
- **Проверки:**
  - [ ] все примеры проходят валидацию;
  - [ ] JSON Schema и TS-типы генерируются одной командой;
  - [ ] пример со `span` за пределами текста или неизвестной меткой отклоняется;
  - [ ] пример ссылки на фрагмент другого доклада отклоняется.
- **Готово, когда:** PR одобрен обеими командами, версия 0.1.0 опубликована в репозитории.

### P0-02. Каркас репозитория и CI

- **Ведёт:** К2 · B. **Ревью:** К1 · лид.
- **После:** —
- **Цель:** единые проверки для всех с первого коммита.
- **Выход:** `backend/` с FastAPI и `/health`; `frontend/` на Vite + React + TypeScript; ruff, mypy, pytest; eslint, tsc, vitest; CI-конвейер; `Makefile` с целями `lint`, `test`, `eval`; `.env.example`; [CODEOWNERS](../CODEOWNERS) с реальными логинами; правило защиты основной ветки.
- **Проверки:**
  - [ ] пустой PR проходит CI;
  - [ ] PR с ошибкой типов падает;
  - [ ] PR в `contracts/` требует одобрения обеих команд.
- **Готово, когда:** CI зелёный, ревьюер из другой команды назначается автоматически.

### P0-03. Сервер и замеры

- **Ведёт:** К2 · A. **Ревью:** К1 · лид.
- **После:** —
- **Цель:** реальные цифры вместо оценок для ADR-002.
- **Выход:** `docs/benchmarks/p0-03-server.md`:
  - GPU и топология (`nvidia-smi topo -m`), драйвер, CUDA, RAM, диски, NVIDIA Container Toolkit;
  - vLLM с Qwen3.6-27B в BF16 на двух картах: время загрузки, время sleep и wake, VRAM, KV-кэш при контексте 32K, токены в секунду на 1 и 8 параллельных запросах;
  - связка режима рассуждения и guided decoding в выбранной версии vLLM;
  - GigaAM-v3, Whisper large-v3 и Qwen3-ASR на 2–3 записях из зала: время, VRAM, характерные ошибки;
  - закреплённые версии образов и библиотек.
- **Проверки:**
  - [ ] каждая цифра получена реальным запуском, рядом указаны команда и версии;
  - [ ] ни одна ячейка не заполнена оценкой; невыполненный замер помечен «не выполнен» с причиной.
- **Готово, когда:** таблица замеров в репозитории, ограничения и риски перечислены.

### P0-04. Эталон

- **Ведёт:** К1 · лид. **Ревью:** К1 · разработчик.
- **После:** —
- **Цель:** данные для `make eval` и выбора моделей.
- **Выход:** `eval/manifest.yaml` с контрольными суммами и правилами нормализации; сами данные вне git:
  - материалы прошлой конференции: не меньше 10 докладов с презентациями и записями;
  - не меньше одной многочасовой записи с разметкой границ (доклад, вопросы, служебное);
  - ручная расшифровка 30–60 минут;
  - 5 эталонных сводок и разметка ключевых фактов по этим докладам;
  - отложенная часть, не меньше 30% докладов.
  
  Пока реальных данных нет — синтетический мини-набор (spec §12).
- **Проверки:**
  - [ ] права на использование материалов подтверждены;
  - [ ] в git нет реальных материалов;
  - [ ] команда 2 может прогнать набор по manifest без ручных шагов.
- **Готово, когда:** manifest и разметка готовы, отложенная часть выделена.

### P0-05. Промпт фактов

- **Ведёт:** К1 · разработчик. **Ревью:** К1 · лид.
- **После:** P0-03.
- **Цель:** проверить, что шаг А (spec §6.7) работает на реальных докладах.
- **Выход:** `prompts/facts/v1.md` и схема ответа; результаты на трёх докладах эталона с ручной оценкой; если рассуждение и guided decoding несовместимы — вариант из двух вызовов.
- **Проверки:**
  - [ ] все три ответа проходят схему;
  - [ ] по ручной оценке выдуманных фактов нет;
  - [ ] обзорный доклад без выводов даёт пустой список выводов и причину;
  - [ ] реплики из заметок попадают в `listener_remarks`, а не в выводы.
- **Готово, когда:** промпт v1 в репозитории, отчёт об оценке приложен к PR.

## Ф1. Справка из слайдов и заметок (недели 2–3)

- **Цель:** вся система поднимается одной командой, в том числе без GPU.

- **Готово, когда:** чистый запуск одной командой описан в README.

### P1-02. Очередь на PostgreSQL

- **Ведёт:** К2 · A. **Ревью:** К1 · лид.
- **После:** P1-01.
- **Цель:** надёжная очередь по ADR-004.
- **Выход:** `workers/queue/` — таблица задач, захват через `SKIP LOCKED`, lease и heartbeat, повторы с backoff, отмена, приоритеты; выбор «своя реализация или procrastinate» записан в ADR-004.
- **Проверки:**
  - [ ] убитый воркер — задача возвращается в очередь после истечения lease;
  - [ ] короткая интерактивная задача обгоняет длинную пакетную;
  - [ ] невалидный вход не повторяется;
  - [ ] старый воркер не перезаписывает результат новой попытки;
  - [ ] результат отменённой задачи не публикуется.
- **Готово, когда:** тесты на эти сценарии проходят в CI.

  - [ ] содержимое PDF совпадает с DOCX;
  - [ ] доклад «не состоялся» не входит в счётчики;
  - [ ] выборка из одной секции даёт счётчики только по ней.
- **Готово, когда:** справка по выбранным докладам собирается во всех трёх форматах.

### P1-12. Редактор сводки

- **Ведёт:** К2 · B. **Ревью:** К1 · разработчик.
- **После:** P1-04, P1-08 (до готовности P1-08 — на заглушках).

- **Выход:** экран сводки: утверждения кликабельны и открывают картинку своего слайда; правка с версиями; статусы доклада.

- **Готово, когда:** сценарий проверки сводки проходит на эталоне.
