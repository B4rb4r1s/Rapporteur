# Установка без интернета

Во время работы «Репортёру» интернет не нужен: приложение обращается только к Ollama,
фронтенд собран в образ, словари и LibreOffice лежат в образе (spec §2). Интернет нужен
только для сборки, поэтому комплект готовят на машине с интернетом и переносят целиком.

## На машине с интернетом

Нужны репозиторий, Docker и make, а в `.env` — `OLLAMA_MODELS_DIR` с нужной моделью
(скачать её: `make pull MODEL=qwen3.5:9b`).

```bash
make bundle
```

Без `MODEL` в комплект идёт модель профиля по умолчанию из `profiles.yaml`. Несколько
моделей: `make bundle MODEL="qwen3.5:9b gemma4:e4b"`. Каталог `bundle/`:

| Файл | Что это |
| --- | --- |
| `images.tar` | образы `rapporteur:local` и Ollama, около 10 ГБ |
| `models/` | манифесты и блобы выбранных моделей, формат каталога Ollama |
| `compose.yaml`, `Makefile` | запуск |
| `.env.example` | настройки: модели из `./models`, образ Ollama по тегу |
| `SHA256SUMS` | контрольные суммы образов и моделей |
| `README.md` | эта инструкция |

Каталог `bundle/` переносится на целевую машину целиком.

## На машине без интернета

Нужны Docker Engine с плагином compose, драйвер NVIDIA и NVIDIA Container Toolkit.
Их пакеты тоже привозятся заранее. В каталоге комплекта:

```bash
make install
```

Команда проверяет контрольные суммы, загружает образы (`docker load`) и создаёт `.env`.
В `.env` задайте `WEB_BIND_ADDRESS` — адрес сервера во внутренней сети, по которому
пользователи откроют интерфейс, и при необходимости `WEB_PORT`. Затем:

```bash
make start
```

`make start` запускает сервисы без сборки и без обращения к реестрам образов
(`--no-build --pull never`). `make up` здесь не подходит: он собирает образ заново.
Интерфейс откроется на `http://<WEB_BIND_ADDRESS>:<WEB_PORT>`. Страница «Управление»
показывает, видит ли приложение Ollama и какие модели в ней есть.

`make ps`, `make logs` и `make down` работают как обычно. База, материалы и справки
хранятся в каталоге `RAPPORTEUR_STORAGE` из `.env`, по умолчанию `storage/` рядом
с комплектом. На сервере лучше задать абсолютный путь вне комплекта, например
`/srv/rapporteur/storage`: тогда новый комплект подхватит те же данные. Каталог создаёт
`make start`, владелец — пользователь, который запускает make. Бэкап — копия каталога
при остановленном приложении (`make down`).

## Обновление

Новый комплект собирается так же. На целевой машине он кладётся в отдельный каталог,
затем: `make install` в новом каталоге, `make down` в старом, `make start` в новом.
`.env` переносится из старого каталога. Если хранилище задано относительным путём,
каталог `storage/` переносится в новый каталог комплекта вместе с `.env`.

## Образ Ollama

В `compose.yaml` образ Ollama закреплён по digest. `docker load` на сервере
со стандартным хранилищем образов digest не сохраняет, поэтому `.env` комплекта задаёт
образ тегом: `OLLAMA_IMAGE=ollama/ollama:0.40.13`. Подмену исключает проверка
`SHA256SUMS` перед загрузкой.

## Порты и сеть

Наружу публикуется только порт интерфейса (`WEB_PORT`, по умолчанию 8000). Ollama
работает во внутренней сети Docker и порт на хосте не занимает: другая Ollama на порту
11434 ей не мешает. Как пользоваться Ollama другого проекта вместо своей — `docs/ollama.md` в репозитории. Исходящего трафика у Ollama нет. У приложения его закрывает сеть
`edge` без NAT, если Docker работает на Linux. Docker Desktop это ограничение
не соблюдает.
