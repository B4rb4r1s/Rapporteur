# Замер привязки материалов (P1-05)

1. Независимо от подсказок разметьте эталонную папку. Для каждого принятого материала
   запишите относительный путь и ожидаемые секцию и номер доклада. Для материала,
   который должен остаться без привязки, явно укажите `talk: null`. Секции и номера
   должны соответствовать реестру конференции. При дедупликации по SHA-256 укажите
   сохранённый путь. Пример структуры разметки:

   ```yaml
   files:
     - path: Секция/01_Иванов/доклад.pptx
       talk: {section: Секция, order: 1}
     - path: Секция/01_Иванов/доклад.pdf
       talk: null
     - path: _общее/программа.pdf
       talk: null
   ```

2. Загрузите папку в новую конференцию. Сохраните ответ `GET /api/v1/conferences/{id}/materials`
   в `data/materials-before.json` до первого подтверждения привязок. Например, из корня:

   ```bash
   curl --fail "http://127.0.0.1:8000/api/v1/conferences/${CONFERENCE_ID}/materials" \
     -o data/materials-before.json
   ```

3. Засеките время от открытия экрана с готовыми подсказками до сохранения исправленных
   привязок. Сверьте выгруженный `conference.yaml` с разметкой.

4. Сохраните разметку в `data/bindings.yaml` и запустите замер из корня репозитория:

   ```bash
   docker compose -f backend/compose.yaml run --rm --build --no-deps \
     -v "$PWD/data:/eval:ro" py rapporteur-backend benchmark-bindings \
     /eval/materials-before.json /eval/bindings.yaml --review-seconds 42
   ```

   Подставьте измеренное время в секундах. Если время не засекали, опустите параметр.
   Команда читает два файла и печатает отчёт. Снимок, разметка и исходные материалы
   хранятся в `data/`, вне git.

**Верные подсказки среди предложенных** считаются по файлам, для которых интерфейс
предвыбрал доклад. **Найденные привязки** показывают, какую долю ожидаемых привязок
интерфейс предложил правильно, включая пропуски в знаменателе. **Верные начальные
решения** также учитывают файлы, которые правильно остались без привязки, в том числе
дополнительные версии презентаций. Если в снимке и разметке разные наборы путей,
команда отклоняет замер.

В отчёт о приёмке добавьте версию проекта, размер набора, три метрики и время ручной
проверки. Здесь приведена процедура замера; результаты на эталоне ещё предстоит получить.
